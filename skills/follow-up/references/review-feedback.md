# Review feedback

1. Read the latest PR revision, threads, responses, requirements, and checks using available PR/tracker tools.
2. Account for each actionable thread: confirmed defect, product/implementation decision, optional suggestion, already addressed, or disputed with evidence.
3. For requested fixes, substantiate the concern, implement the agreed correction, and validate the affected behavior. Bring consequential unresolved decisions to the user before implementing them. Keep routine fixes within the accepted plan moving.
4. When authorized, reply in the existing thread with the correction and evidence or a concise explanation of disagreement. Resolve threads only under the workspace's rules and after verifying their disposition.
5. If approval is requested or already authorized, review the current revision and remaining blockers before submitting it. Treat merging as a separate action requiring its own authorization.

Summarize thread outcomes, validation, and unresolved blockers. If remote access is unavailable, preserve local fixes or drafted replies and identify the external actions still undone.
