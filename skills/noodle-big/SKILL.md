# Noodle Big

Keep the discussion at product level. Use workspace guidance, existing plans, and available tracker/document read tools to ground decisions.

1. **Clarify the initiative.** Establish the problem, audiences, current workflows, and intended value. Record decisions and assumptions as the discussion progresses.
2. **Define outcomes.** Explore the major user journeys, interactions with existing products, consequential failures, and observable success. Ask focused questions in rounds rather than presenting an exhaustive questionnaire.
3. **Set release scope.** Separate the smallest useful release from later ambitions. Agree on milestones, exclusions, dependencies, and discovery needed for unresolved risks. Discuss implementation constraints only when they change the product promise.
4. **Create and validate tasks, if desired.** Draft an initiative brief and coherent outcome-based tasks, with acceptance criteria, likely repository ownership, dependencies, and a concrete first task. Review the plan with the user. Use the configured tracker hierarchy or local tickets; publish within existing authorization.

Finish when the overall product scope is agreed and the first milestone is actionable. Name uncertainty in later milestones instead of inventing precise schedules or commitments.

When the user wants to design a task's implementation, use `noodle`'s implementation planning path if installed. Otherwise inspect that task's code and contracts, discuss scaffolding and core logic with the user, and record an agreed implementation sequence and validation plan. Keep broad product exploration and implementation design as distinct phases.
