# Noodle

Read the conversation, applicable workspace guidance, and related task. Use available documents and read tools; a tracker connector/CLI is needed only for remote tickets.

Choose the planning path from the user's intent:

- **Product planning:** Who needs this, what should change for them, and what belongs in scope? Read [product planning](references/product.md).
- **Implementation planning:** The outcome is defined; how should the change work in this codebase? Read [implementation planning](references/implementation.md).

If both are needed, settle the product outcome first, then explore implementation. Ask only when the intended path is unclear. For whole-project product exploration, suggest `noodle-big`; this skill still handles a focused product task independently.

Task creation is optional: confirm whether the user wants a discussion summary or tasks. Use the configured tracker or local format and publish only within existing authorization. If remote access is unavailable, return complete drafts. Planning does not itself start implementation.
