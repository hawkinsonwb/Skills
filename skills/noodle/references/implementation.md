# Implementation planning

1. **Establish the outcome.** Read the agreed task and acceptance criteria. Resolve missing product decisions before designing behavior around them.
2. **Inspect the current design.** Read relevant code, callers, models, contracts, and repository guidance. Identify affected repositories and existing patterns.
3. **Discuss the approach.** Show the needed scaffolding and outline core logic in plain language or pseudocode. Compare alternatives only where they affect correctness, performance, architecture, or the user's experience. Surface consequential decisions for user alignment.
4. **Record the plan.** Capture the agreed approach, contracts, implementation sequence, validation, and open blockers. If tasks are desired, create or update them using the configured format and validate them with the user.

Use repository read tools; report an access gap rather than guessing the existing implementation. Finish with a plan that `work` can execute. Keep this phase focused on design; edit application code when delivery is requested.
